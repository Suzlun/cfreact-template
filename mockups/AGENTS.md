# App Prototypes

- OpenCode owns mock creation and planning. Pair each public `apps/<app>` with one integrated React mock in `mockups/<app>/src/**`. `App.tsx` implements the journey and `App.stories.tsx` declares its initial screens and states.
- Update source and owner-confirmed `request.md` together. Confirmed Request supplies product intent. Recheck all affected apps, Requests, and Changes when shared UI decisions, routes, or scenarios change.
- Import shared implementations directly through public `@cfreact-template/ui` subpaths. Use fixtures and local state, without actual API or database access. Apply the repository's React Compiler rules.
- Shared `mockups/.storybook` and `tsconfig.json` use the existing UI Vite configuration, including Tailwind CSS 4 and React Compiler. `pnpm storybook:mockup` serves the mock catalog; `pnpm storybook:host` serves registered projects through one origin. Dev Container is the standard runtime. `pnpm build:mockup` builds to ignored `mockups/dist`.
- Use args for initial conditions and React state for interactions. Reset the mock when its initial conditions change. Keep navigation, form entry, and recovery inside the integrated mock. Check every relevant story on desktop and mobile using a real browser.
- Current `main` stories are `Home`, `Users`, `EmptyUsers`, `UsersLoading`, `UsersError`, and `CreateError`. Their IDs are `main--home`, `main--users`, `main--empty-users`, `main--users-loading`, `main--users-error`, and `main--create-error`.
- Request's `UI Mock References` identifies the app through exact paths such as `mockups/main/src/App.stories.tsx#Home` and `mockups/main/src/App.stories.tsx#UsersError`. Proposal's `Design Source` uses the same references with adopted screen/flow/state scope and owner adoption evidence.
- Each app's N routes/scenarios and M Changes have a many-to-many relationship. A Change references multiple app prototypes only when its confirmed outcomes require them. Keep root `mockups/` and its app prototypes when Changes are archived. Existing Storybook remains the shared UI catalog.
- After Planning Ready, production implementation follows `PRODUCTION_UI -> WIRING -> POLISH -> REVIEW` in the scoped `apps/<app>` and shared UI. Product decisions return to the OpenCode planning phase. During implementation, planning-file edits are limited to task progress.
